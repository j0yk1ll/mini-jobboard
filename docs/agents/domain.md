# Domain docs

This repo uses a single-context layout.

## Before exploring the codebase

- Read `GLOSSARY.md` at the repository root when it exists.
- Read the ADRs in `docs/adr/` that relate to the area you are working in.

If either is absent, proceed silently. The domain-modeling skill creates these files as terms and decisions are settled.

## Use the glossary's vocabulary

Use glossary terms in tickets, refactor proposals, hypotheses, and test names. When a relevant term is missing or ambiguous, flag it for domain modeling.

## Flag ADR conflicts

If a proposal conflicts with an existing ADR, cite the ADR and explain why the decision may need revisiting.
